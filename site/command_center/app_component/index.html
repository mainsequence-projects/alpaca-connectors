    Asset Registry AppComponent¶

    Goal¶

    The project includes a Command Center AppComponent configuration for the workspace:

    • Alpaca Assets Registry

    This widget is meant to let a user register one Alpaca-backed asset directly by ticker through the project's FastAPI surface.

    Widget Contract¶

    The mounted widget type is:

    • app-component

    The widget is configured against this API route:

    • POST /v1/app-components/assets/register-ticker

    That route is intentionally simple:

    • request body: one ticker plus optional operational flags
    • response body: explicit registration result for exactly one ticker

    This is an AppComponent flow, not a data-node-table-visualizer flow, so the response is a normal typed FastAPI model instead of a table-widget SDK contract.

    API Decision¶

    For this widget, the default generated AppComponent form is sufficient.

    We did not add a custom EditableFormDefinition because the operation only needs:

    • ticker
    • include_non_tradable
    • timeout

    That matches the Command Center rule to prefer autogenerated forms unless the UX truly needs custom sections or field-level specialization.

    Workspace Builder¶

    The repo owns the workspace payload builder in:

    • src/command_center/workspaces.py

    and a thin file generator in:

    • scripts/build_alpaca_assets_registry_workspace.py

    Example:

    .venv/bin/python scripts/build_alpaca_assets_registry_workspace.py --fastapi-release-id 701

    This writes:

    • command_center/workspaces/alpaca_assets_registry.workspace.yaml

    The generated workspace update mounts one widget:

    • title: Register Asset By Ticker
    • widget id: app-component
    • target mode: main-sequence-resource-release
    • operation: POST /v1/app-components/assets/register-ticker

    Why The Widget Uses A FastAPI Release¶

    The intended workspace target is a deployed MainSequence FastAPI resource release, not a localhost URL.

    The widget props therefore use:

    • apiTargetMode: main-sequence-resource-release
    • mainSequenceResourceRelease.releaseId

    instead of a hardcoded local apiBaseUrl.

    Source Of Truth For The Widget Payload¶

    The local skill docs did not include a concrete mounted AppComponent payload example, so the widget payload was verified against the local Command Center frontend source:

    • CommandCenter/src/widgets/core/app-component/definition.ts
    • CommandCenter/src/widgets/core/app-component/appComponentModel.ts

    Important confirmed details:

    • widget id is app-component
    • the widget can target a Main Sequence FastAPI resource release directly
    • method, path, and requestBodyContentType are persisted widget props
    • runtime OpenAPI discovery can generate the form from the selected operation

    Current Limitation¶

    Applying the generated workspace update to the live platform still requires a valid authenticated MainSequence CLI or SDK session.

    When auth is available, apply the generated file with:

    mainsequence cc workspace update 3 --file command_center/workspaces/alpaca_assets_registry.workspace.yaml
